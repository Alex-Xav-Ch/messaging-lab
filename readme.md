## What is Socket.IO?

Socket.IO is a **real-time communication library** built on top of WebSocket. It adds advanced features that the native WebSocket protocol does not have:

- ✅ **Named event system** (`emit` / `on`)
- ✅ **Automatic reconnection** if the network drops
- ✅ **Rooms and Namespaces** to group clients
- ✅ **Automatic fallback** to HTTP long-polling if WebSocket is unavailable
- ✅ **Broadcast** to send messages to multiple clients at once

Socket.IO is split into **two separate packages**:

| Package             | Role                                         | Install                        |
|---------------------|----------------------------------------------|--------------------------------|
| `socket.io`         | Server — runs on Node.js                     | `npm install socket.io`        |
| `socket.io-client`  | Client — runs in Node.js or the browser      | `npm install socket.io-client` |


```bash
cd ejemplo2-socketio
```


## How to Run

> ⚠️ **Important:** You need **two terminals open at the same time**.

### Terminal 1 — Start the Server

```bash
node servidor.js
```

You should see:
```
✅ Servidor Socket.IO corriendo en http://localhost:3000
```

The server is now **waiting for connections**. Do not close it.

---

### Terminal 2 — Run the Client

```bash
node cliente.js
```

You should see:
```
✅ Conectado al servidor, ID: abc123xyz
📨 Mensaje recibido del servidor: "Hola Mundo"
🔌 Desconectado del servidor
```

And in Terminal 1 (server):
```
🔌 Cliente conectado: abc123xyz
📤 Mensaje emitido al cliente: "Hola Mundo"
❌ Cliente desconectado: abc123xyz
```

> The `ID` is a unique identifier automatically generated by Socket.IO for each client.

## Communication Flow

```
CLIENT                                    SERVER
   │                                          │
   │──── HTTP connection request ────────────▶│
   │◀─── Upgrade to Socket.IO ───────────────│
   │                                          │
   │  Event: "connect"                        │  Event: "connection"
   │  socket.id assigned                      │  socket.id assigned
   │                                          │
   │                                          │  socket.emit("mensaje", "Hola Mundo")
   │◀──── Event "mensaje" ───────────────────│
   │      data = "Hola Mundo"                 │
   │                                          │
   │  Event "mensaje" received                │
   │  socket.disconnect()                     │
   │──── Disconnection ──────────────────────▶│
   │                                          │  Event: "disconnect"
   │  Event: "disconnect"                     │
   │                                          │
```

## Code Explained

### `servidor.js`

```javascript
const { Server } = require("socket.io");
```
Imports the `Server` class from the `socket.io` package.

```javascript
const io = new Server(PORT, {
  cors: { origin: "*" },
});
```
Creates the Socket.IO server on port `3000`. The `cors: { origin: "*" }` option allows connections from any origin — useful for development testing.

```javascript
io.on("connection", (socket) => { ... });
```
Event fired **every time a client connects**. The `socket` parameter is that client's individual instance, with its own unique `socket.id`.

```javascript
socket.emit("mensaje", "Hola Mundo");
```
`emit()` is Socket.IO's core function. It takes two arguments:
- **Event name** (`"mensaje"`) — can be any string you define
- **Data to send** (`"Hola Mundo"`) — can be a string, number, object, array, etc.

```javascript
socket.on("disconnect", () => { ... });
```
Event fired when the client closes the connection.

---

### `cliente.js`

```javascript
const { io } = require("socket.io-client");
```
Imports the `io` function from the Socket.IO client package.

```javascript
const socket = io("http://localhost:3000");
```
Establishes the connection to the server. Note it uses `http://` (not `ws://`), because Socket.IO negotiates the protocol internally.

```javascript
socket.on("connect", () => {
  console.log("✅ Connected, ID:", socket.id);
});
```
The `"connect"` event confirms a successful connection. `socket.id` holds the unique identifier assigned by the server.

```javascript
socket.on("mensaje", (data) => {
  console.log(`📨 Message: "${data}"`);
  socket.disconnect();
});
```
Listens for the custom event named `"mensaje"`. The name must match exactly what the server uses in `socket.emit("mensaje", ...)`. Once received, the client disconnects.

## Common Errors

### ❌ `Error: xhr poll error` or `connect_error`

**Cause:** The client cannot reach the server.

**Fix:** Make sure the server is running before executing the client.

```bash
# Terminal 1 first:
node servidor.js

# Terminal 2 after:
node cliente.js
```

---

### ❌ `Error: listen EADDRINUSE :::3000`

**Cause:** Port 3000 is already in use (another process or another server instance).

**Fix:** Change the port in both files:
```javascript
// servidor.js
const PORT = 4000;

// cliente.js
const socket = io("http://localhost:4000");
```

---

### ❌ `Error: Cannot find module 'socket.io'`

**Cause:** Dependencies were not installed.

**Fix:**
```bash
npm install
```

---

### ❌ Client receives the event but data is `undefined`

**Cause:** The event name in `emit` and `on` do not match.

**Fix:** Make sure they are exactly the same string:
```javascript
// Server emits:
socket.emit("mensaje", "Hola Mundo");  // ← "mensaje"

// Client listens:
socket.on("mensaje", (data) => { ... });  // ← "mensaje" (must be identical)
```

## Key Concepts

| Term             | Meaning                                                                                  |
|------------------|------------------------------------------------------------------------------------------|
| `emit()`         | Sends a named event to the other end of the connection                                   |
| `on()`           | Registers a listener for a specific named event                                          |
| `socket.id`      | Unique ID generated by Socket.IO for each connected client                               |
| Event            | A message identified by a name string; can carry any data as a payload                  |
| Namespace        | Virtual channel within the same server (default is `/`)                                  |
| Room             | Group of sockets; allows sending messages to a subset of clients                         |
| `broadcast`      | Send a message to all clients **except** the sender                                      |
| CORS             | Cross-Origin Resource Sharing; policy controlling which origins can connect              |
| Long-polling     | Socket.IO's HTTP fallback when WebSocket is not available                                |

## WebSocket vs Socket.IO

| Feature                  | WebSocket (`ws`)             | Socket.IO                          |
|--------------------------|------------------------------|------------------------------------|
| Protocol                 | Raw WebSocket                | WebSocket + HTTP long-polling      |
| Named events             | ❌ Only generic `message`    | ✅ Any custom name                 |
| Automatic reconnection   | ❌ Manual                    | ✅ Built-in                        |
| Rooms / Namespaces       | ❌ No                        | ✅ Yes                             |
| Broadcast                | Manual                       | ✅ `io.emit()` / `socket.broadcast`|
| Browser compatibility    | High (native)                | Very high (with fallbacks)         |
| Size / weight            | Very lightweight             | Heavier                            |
| Learning curve           | Low                          | Medium                             |
| Best for                 | Simple apps, low-level       | Complex apps, chats, games         |
